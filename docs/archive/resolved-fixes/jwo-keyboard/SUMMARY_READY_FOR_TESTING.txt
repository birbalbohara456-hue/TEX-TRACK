EXACT ROOT CAUSE (Summary)
═══════════════════════════════════════════════════════════════════════════════

SYMPTOM:
  After opening/closing Dashboard top menus (Alt+M or Alt+T) with Esc,
  keyboard focus is lost to document.body, breaking keyboard-first navigation.

ROOT CAUSE:
  1. Menu items focused before closing have IDs (e.g., "masters-item-0")
  2. When menu closes, Blazor removes menu items from DOM
  3. Browser automatically moves focus to document.body (standard behavior
	 when focused element is removed from DOM)
  4. Generic focus-to-page-root logic searches inside .workspace element
  5. Dashboard exists OUTSIDE .workspace, so fallback fails
  6. Focus stays on body, keyboard events stop working

SOLUTION:
  1. BEFORE opening menu: Capture currently focused Dashboard item ID
  2. Store in: window.texTrackDashboardReturnFocusId
  3. AFTER closing menu: Query and restore that specific element
  4. Fallback: If element no longer exists, restore to dashboard-page-root
  5. Result: Focus returns to Dashboard, keyboard works immediately

SUPPORT & TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

If Acceptance Test Fails:

Q: Keyboard doesn't work after Esc closes menu?
A: Check document.activeElement in browser console.
   If it's <body>, the focus restoration didn't work.
   Verify window.texTrackDashboardReturnFocusId contains correct ID.

Q: JavaScript errors in console?
A: Check browser console (F12) for red error messages.
   Verify both new functions exist: typeof window.texTrackRememberDashboardFocus
   If functions don't exist, verify App.razor was saved correctly.

Q: Focus goes to wrong element?
A: Check that Dashboard item IDs are: dashboard-item-0, dashboard-item-1, etc.
   Verify Dashboard root ID is: dashboard-page-root
   Fallback logic should handle any mismatch.

Q: Menu doesn't open or close?
A: This is a separate issue from the focus fix.
   Verify menu controller in App.razor is working.
   Test Alt+M and Alt+T keyboard shortcuts.
